## Установка и запуск

### Windows не даёт запустить установщик

SmartScreen показывает «Система Windows защитила ваш компьютер», потому что установщик не подписан сертификатом издателя. Нажмите «Подробнее», затем «Выполнить в любом случае». Скачивайте установщик только со [страницы релизов](https://github.com/Focusniks/NetTrace-desktop/releases/latest).

### Окно пустое или программа не открывается

NetTrace использует WebView2. В Windows 10 и 11 он есть, но может быть удалён или повреждён. Установите [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) с сайта Microsoft и запустите программу снова.

### Обновление не устанавливается

| Сообщение или симптом | Что делать |
|---|---|
| «Не удалось обновить NetTrace» | Проверьте доступ к `github.com`; нажмите «Повторить» |
| Проверка не находит новую версию | Откройте **Помощь → О программе**: там время и результат последней проверки |
| Обновление предлагается снова и снова | Нажмите «Пропустить эту версию» или установите её |
| Нет доступа к GitHub | Скачайте установщик вручную и запустите поверх установленной версии |

## Живой захват

### «Захват недоступен: не найден драйвер захвата Npcap»

1. Установите [Npcap](https://npcap.com).
2. Нажмите «Проверить снова» в списке интерфейсов.
3. Если не помогло — перезапустите NetTrace.

### Список интерфейсов пуст

| Причина | Решение |
|---|---|
| Npcap установлен с флажком «только для администраторов» | Запустите NetTrace от имени администратора или переустановите Npcap без флажка |
| Служба Npcap остановлена | В командной строке администратора: `sc start npcap` |
| Установлен старый WinPcap вместо Npcap | Удалите WinPcap, поставьте Npcap |

### «Не удалось открыть интерфейс»

- Интерфейс отключён или удалён — выберите другой.
- Нет прав — см. предыдущий пункт.
- Интерфейс занят другой программой в монопольном режиме — закройте её.

### «Ошибка в фильтре захвата»

Фильтр захвата пишется на языке BPF, а не на языке фильтров отображения. Правильно: `tcp port 443`. Неправильно: `tcp.port == 443`. Примеры — в разделе [живой захват](capture.md).

### Захват идёт, но пакетов нет

| Проверьте | Как |
|---|---|
| Тот ли интерфейс | Выберите тот, у которого есть IP-адрес вашей сети |
| Не слишком ли узкий фильтр захвата | Запустите без фильтра |
| Локальный ли это трафик | Для `127.0.0.1` нужен интерфейс `loopback` |
| Не скрывает ли пакеты фильтр отображения | Нажмите «Сбросить» |

### Растёт счётчик «отброшено»

Драйвер не успевает передавать пакеты. Задайте фильтр захвата, уменьшите «Макс. байт с кадра», закройте тяжёлые панели на время захвата.

### Не вижу чужой трафик в сети

В коммутируемой сети до вашего компьютера доходят только его собственные кадры и широковещательные. Неразборчивый режим этого не меняет. Нужен порт зеркалирования на коммутаторе или захват на самом узле.

## Файлы

### «Неизвестный формат файла»

NetTrace читает PCAP и PCAPNG. Проверьте:

- не сжат ли файл (`.gz`, `.zip`) — распакуйте;
- не другой ли это формат (`.etl`, `.cap` от Network Monitor, `.snoop`) — преобразуйте его в PCAPNG сторонней утилитой.

### «Файл обрезан: последний пакет неполный»

Захват прервался во время записи или файл скопирован не полностью. Всё, что прочиталось, доступно.

### «Файл захвата повреждён»

Структура файла нарушена. Откроется часть до повреждения. Попробуйте получить файл заново.

### «Не удалось прочитать пакет из файла»

Файл изменён, перемещён или стал недоступен после открытия — например, отключился сетевой диск. Откройте файл заново.

### Сохранение не работает

| Сообщение | Причина |
|---|---|
| «Дождитесь окончания индексирования» | Файл ещё читается |
| «Нельзя перезаписать открытый файл» | Выберите другое имя |
| «Не удалось сохранить файл» | Нет прав на папку или нет места на диске |

## Фильтры и поиск

### Фильтр подсвечен красным

В выражении ошибка; под строкой — её описание. Частые случаи разобраны в разделе [фильтры](filters.md).

### Фильтр верный, но пакетов нет

- Значения строк чувствительны к регистру: `http.host == Example.com` не найдёт `example.com`.
- Поле есть не во всех пакетах протокола: `http.host` есть только в запросах.
- `tcp.port == 53` не найдёт DNS по UDP — нужен `udp.port == 53` или просто `dns`.
- Протокол мог не распознаться: проверьте колонку «Протокол».

### Фильтр работает медленно

Он использует поле, требующее разбора каждого пакета. Добавьте быстрое условие через `&&` — см. [пределы и производительность](limits.md).

### Поиск ничего не находит

- Поиск идёт только по отображаемым пакетам — сбросьте фильтр.
- Строка может быть в зашифрованных данных TLS — там её не найти.
- Для hex-поиска вводите байты парами: `16 03 01`.

## Разбор пакетов

### Пакет показан как TCP, а не как HTTP или TLS

| Причина | Пояснение |
|---|---|
| Это сегмент без начала сообщения | Сообщение началось в предыдущем сегменте; сборка сегментов пока не поддерживается |
| Нестандартный порт и нетипичное начало данных | Протокол определяется по порту и по первым байтам |
| Протокол не поддерживается | См. [список протоколов](protocols.md) |

Данные такого соединения целиком видны в [содержимом потока](follow.md).

### Много «повреждённых» пакетов

- Захват сделан с малой длиной кадра — пакеты обрезаны.
- На нестандартном порту идёт другой протокол, принятый за известный.
- Файл действительно повреждён.

### Много повторных передач сразу у всех

Скорее всего, это особенность захвата, а не сети: при захвате на зеркальном порту или на нескольких интерфейсах каждый пакет попадает в файл дважды.

### Не видно сертификат сервера

В TLS 1.3 сертификат передаётся зашифрованным. Это свойство протокола.

## Интерфейс

### Пропала боковая панель или список

Панель могла быть развёрнута на всё окно. Нажмите кнопку восстановления в её заголовке или закройте панель.

### Сбились колонки

Правая кнопка по заголовку списка → «Сбросить колонки».

### Строки одного цвета

Раскраска выключена — нажмите кнопку с палитрой. Либо правила были удалены: **Правка → Правила раскраски… → По умолчанию**.

## Если ничего не помогло

Создайте [issue](https://github.com/Focusniks/NetTrace-desktop/issues) и укажите:

1. версию NetTrace (**Помощь → О программе**) и версию Windows;
2. что вы делали и что произошло;
3. текст сообщения об ошибке;
4. если возможно — небольшой файл захвата, на котором проблема воспроизводится.

> **Важно.** Не прикладывайте захваты с реальными паролями, cookie и внутренними адресами. Сначала отфильтруйте нужные пакеты и убедитесь, что в них нет чувствительных данных.
