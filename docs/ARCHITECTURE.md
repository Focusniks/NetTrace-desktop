# NetTrace — архитектура

Локальный desktop-анализатор PCAP/PCAPNG. Пользователь сам исследует захват;
приложение показывает факты (пакеты, поля, потоки, счётчики) и не делает выводов.

## Слои

```
apps/desktop/            Tauri-приложение
  src-tauri/             тонкий IPC-слой: команды → engine, события прогресса
  src/                   React + TypeScript UI (не знает внутренностей парсера)
crates/
  model/                 DTO-контракт backend ↔ UI (Packet, Flow, Host, Conversation,
                         Protocol, TimelineEvent, PacketField …). Только serde.
  packet/                безопасный байтовый курсор, адреса (MAC/IPv4/IPv6), link types, время
  capture/               потоковое чтение PCAP/PCAPNG (+ запись PCAP), трейт PacketSource
  live/                  живой захват: Npcap/libpcap загружается в рантайме (единственный
                         модуль с unsafe — FFI), список интерфейсов, BPF-фильтр захвата
  protocol/              диссекторы и реестр (Ethernet, 802.1Q, ARP, IPv4/6, ICMP/v6,
                         TCP, UDP, DNS, DHCP, HTTP/1.x, TLS, NTP), реестр полей фильтра
  flow/                  отслеживание TCP/UDP-потоков, TCP-анализ (ретрансмиссии, dup ACK,
                         out-of-order, zero window, RTT, рукопожатие, FIN/RST)
  analysis/              агрегаты: узлы, соединения, иерархия протоколов, I/O-график,
                         длины пакетов, временная шкала, технические индикаторы
  storage/               компактный индекс метаданных пакетов + ленивое чтение байтов из файла
  query/                 язык display filter: лексер → парсер → AST → типизированная
                         компиляция по реестру полей → вычисление по трейту FieldSource
  engine/                оркестрация сессии: фоновая индексация, представления (фильтр +
                         сортировка), детали пакета, поиск, статистика
  testkit/               построители пакетов и генератор PCAP-фикстур (только для тестов)
```

Граф зависимостей (стрелка = «зависит от»):

```
model ◄── protocol ◄──┐
packet ◄── capture    │
  ▲   ◄── protocol    ├── engine ◄── desktop (src-tauri)
  ├──── flow ◄────────┤
  ├──── storage ◄─────┤
  └──── analysis ◄────┤
model ◄── query ◄─────┘
```

`query` не знает про индекс и диссекторы: движок реализует `FieldSource`. `flow` получает
узкую структуру `FlowPacket`, а не результат диссекции. UI получает только типы из `model`.

## Конвейер обработки файла

```
PCAP/PCAPNG ──► capture::CaptureReader (BufReader, последовательно, offset каждой записи)
             ──► protocol::dissect (режим Summary: без дерева и строк)
             ──► batch (8192 пакета) ──► write-lock индекса:
                    storage::PacketIndex.push(PacketMeta 64 байта)
                    flow::FlowTable.process  → stream id, флаги TCP-анализа, RTT
                    analysis::Accumulators   → узлы, соединения, иерархия, события
             ──► событие прогресса в UI каждые ~100 мс
```

В памяти хранятся только метаданные (~64 байта на пакет + 4 байта в списке потока).
Байты пакета читаются позиционным чтением из файла по требованию: строки видимой
части списка, детали выбранного пакета, поля фильтра, которых нет в индексе.

Пока индексация идёт, UI уже может листать, фильтровать и открывать пакеты
(чтение под read-lock, индексатор берёт write-lock только на применение батча).

## Живой захват

```
Npcap/libpcap ──► live::LiveSource ──► поток-рекордер ──► временный PCAP (%TEMP%/NetTrace)
                                                             │ (дописывается)
                                       engine::TailReader ◄──┘ ждёт новых байт вместо EOF
                                             └──► тот же индексатор, что и для файлов
```

Индексатор в режиме захвата применяет каждый пакет сразу, поэтому список, фильтры,
потоки и статистика обновляются в реальном времени; отфильтрованное представление
пересчитывается раз в секунду. После остановки захват — обычный файл: его можно
сохранить (PCAP/PCAPNG); временный файл удаляется при закрытии. Без установленного
Npcap приложение работает в режиме файлов и объясняет, что нужно установить.

## Display filter

Поля делятся на «индексные» (frame.number, ip.addr, tcp.port, tcp.stream, флаги TCP,
наличие протокола, tcp.analysis.*, frame.time_relative …) — вычисляются по `PacketMeta`
без чтения файла, параллельно (rayon) — и «глубокие» (dns.qry.name, http.host,
tls.handshake.extensions_server_name, ip.ttl …) — для них пакет читается и
диссектируется в режиме Values (дерево без строк отображения).

## Безопасность

PCAP — недоверенный вход. Весь разбор идёт через `packet::Cursor` с проверкой границ,
без `unsafe`. Ошибка разбора слоя превращается в узел `[Malformed]` и не прерывает
обработку файла. Дополнительно каждый вызов диссектора обёрнут в `catch_unwind`.
Лимиты: размер записи ≤ 256 КиБ, размер блока PCAPNG ≤ 16 МиБ, глубина вложенности
слоёв, число переходов при DNS-компрессии. UI никогда не интерпретирует содержимое
пакетов как HTML/URL, не открывает ссылки и не делает сетевых запросов
(CSP Tauri запрещает внешние источники, плагины shell/opener не подключены).

## SQLite

В MVP не используется: индекс в памяти достаточно компактен для миллионов пакетов.
`storage` скрывает хранение за типом `PacketIndex`, поэтому персистентный кэш индекса
(SQLite) можно добавить без изменения остальных слоёв.

## Расширение

* Новый диссектор: реализовать `protocol::Dissector`/`AppDissector`, зарегистрировать
  в `Registry::with_builtins`, добавить поля в `protocol::fields`. UI не меняется —
  дерево деталей и фильтр работают по общей модели.
* Live capture: реализовать `capture::PacketSource` поверх libpcap/Npcap; движок
  принимает любой источник записей.
* Английский язык: `apps/desktop/src/i18n` — словари; диссекторы отдают
  языконезависимые id полей, подписи переводит UI.
